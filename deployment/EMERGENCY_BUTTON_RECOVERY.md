# 비상벨 재누름 / 슬립 복원

P4와 S3를 함께 업데이트해야 합니다. WROOM, Pi, 서버 변경은 없습니다.
웹 비상 수락 연결(`emergency.ack` 지원)은 별도 작업이며 이 변경으로 완성되지 않습니다.

- 버튼을 3초 누르면 비상 시작을 요청합니다. 계속 누르고 있어도 다시 취소되지 않습니다.
- 버튼을 놓았다가 다시 3초 누르면 같은 비상 이벤트를 취소합니다.
- 비상 수락 후에도 이벤트 번호를 유지합니다. 다시 누르면 해당 비상 통화를 종료합니다.
- 통화 종료는 기존 WROOM/S3 준비 응답 절차 완료 후 S3에 확정합니다.
- S3는 P4 확인 전 이벤트 번호를 지우지 않습니다. 1초 간격 최대 6회 송신 후 멈춥니다.
  확인을 못 받으면 버튼을 놓고 다시 3초 눌러 같은 취소를 재시도합니다.
- 이전 이벤트의 확인 응답은 무시합니다. P4는 가장 최근 종료 이벤트의 재요청에 END를 다시 보냅니다.
- P4는 비상 대기 중 슬립 전환을 보류하며 기존 슬립/프로젝터/음악 정책을 유지합니다.
  비상 LED는 슬립 출력 차단보다 우선합니다. 종료 시 최근 감지가 있으면 깨우고,
  감지가 없으면 기존 슬립을 유지합니다. 통화 중 상태 복원은 기존 통화 스냅샷을 사용합니다.

## 로컬 응답 형식
P4 → S3: SERVICE_EMERGENCY / CMD_DATA, payload 5 bytes.
첫 바이트 0x80=비상 시작 처리, 0x81=비상 수락 처리, 0x82=종료 처리.
나머지 4바이트는 원래 버튼 이벤트 번호(big endian).
비상 취소 응답은 P4의 상태 해제 및 WROOM STOP 큐 등록 확인입니다.
비상음 자체가 실제로 멈췄는지 측정한 응답은 아니므로 청취 검증이 필요합니다.
연결 단절, 보드 단독 재부팅, 6회 연속 유실을 무조건 복구한다고 보장하지 않습니다.

## 실기 확인
1. 슬립 OFF에서 3초 START → 놓기 → 다시 3초 CANCEL. 비상음/LED 해제 확인.
2. 실제 슬립 상태에서 동일 동작. 사람 감지가 없으면 원래 슬립 유지 확인.
3. 비상 중 사람 감지 후 종료. 최근 감지에 따라 정상 모드 복귀 확인.
4. 로컬 테스트의 `ack 1`로 비상 통화 수락 후 버튼 재누름. CALL END와 비상음 종료 확인.
   웹 소유 통화와 로컬 테스트를 동시에 실행하지 않습니다.
5. P4 확인 응답이 없는 조건에서 S3가 6회 후 멈추고, 같은 취소를 수동 재시도하는지 확인.
6. 통화 준비 응답 실패 시 END를 성공으로 표시하지 않는지 확인.

호스트 테스트: P4 13개, S3 3개. 실제 ESP-IDF/PlatformIO 빌드와 실기 검증은 별도입니다.
