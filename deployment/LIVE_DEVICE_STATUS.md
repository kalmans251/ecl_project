# 일반 장치 상태 자동 갱신

## 적용
P4 펌웨어, 난간 Pi, Spring Boot 서버를 함께 업데이트합니다.
WROOM/S3 펌웨어 변경이나 DB/토큰 초기화는 필요 없습니다.
Pi는 기존 `--monitor-url` 설정으로 실행하고, 웹 조회 요청이 있을 때만 일반 상태를 수집합니다.
브라우저는 Ctrl+F5로 갱신합니다.

## 실제 갱신 경로
Pi → P4 버전 지정 SYSTEM 상태 요청 → 일치하는 APPLY 응답 검증 →
서버 telemetry → 기존 웹 2초 조회 → 상태 표시.
예전 `ping`/`query` 응답과 호환되도록 일반 query의 1바이트 응답은 유지합니다.
새 자동 수집은 SYSTEM/APPLY, 원래 명령 STATUS_REQUEST, 추가 payload 01을 사용합니다.
응답 detail은 버전 1, 16바이트입니다. 구형 P4의 거부/짧은 응답은 최신 상태로 등록하지 않습니다.

수집 항목: 전원 모드/출력 제어 상태, LED 활성/모드, 날씨 효과,
프로젝터 출력 제어 상태, 슬립 설정/실제 슬립 상태, 감지 소스,
P4 음악 재생 정책, 누적 감지 수.
이 값은 P4 컨트롤러가 보유한 상태이며 실제 전압/빛/소리를 측정했다는 뜻은 아닙니다.
음악 재생 시간/곡명은 기존 WROOM 음악 조회 경로를 계속 사용합니다.
볼륨, 배터리 퍼센트, 충전량 등 이 응답에 없는 항목은 추정하거나 0으로 만들지 않습니다.

## 통신 예산
- 모니터링/기능 테스트 화면에서 선택한 난간만 조회합니다. 목록에 보인다는 이유만으로 조회하지 않습니다.
- 웹은 기존 상태 갱신 때 `/api/portal/status-demand`로 선택 목록을 갱신합니다.
  서버는 사용자 권한을 검사하고 6초짜리 화면별 요청을 유지합니다.
  여러 사용자의 요청은 게이트웨이/난간별로 합쳐 2초마다 Pi로 전달합니다.
- 숨겨진 탭은 빈 목록을 보냅니다. 종료/단절 시 서버 요청은 6초 후 만료되고,
  Pi도 6초 동안 갱신이 없으면 중단합니다. 전달 지연을 포함하여 즉시 중단은 아닙니다.
  이미 송신된 조회는 완료될 수 있습니다. 재연결 직후에는 새 요청 전까지 조회하지 않습니다.
- 비상 이벤트 확인, 통화 관리, 기존 음악/레이더 수집 정책은 변경하지 않습니다.
  이번 변경이 모든 백그라운드 PLC 통신을 중단한다는 뜻은 아닙니다.
- 난간별 최소 5초 간격, 전체 조회 시작 간 최소 0.5초, 응답 대기 최대 0.6초.
  난간 수/타임아웃/다른 제어에 따라 실제 간격은 늘어납니다.
- 기존 PLC 리더와 토큰/난간/소스 검증을 재사용합니다. 수신 프로세스를 추가하지 않습니다.
- 사용자 제어, 통화, 비상, 미확정 세션, keepalive가 우선이며 일반 조회는 보류됩니다.
- 실패 시 오래된 값을 새로운 수신 시각으로 올리지 않습니다.

## 화면
P4 마지막 확인 상태와 경과 시간을 표시합니다. 15초 이상 새 상태가 없으면
상태 지연을 표시합니다. 편집 중인 제어 설정을 수신값으로 덮어쓰지 않습니다.
서버 조회 자체가 실패해도 이전 값을 현재 정상 상태처럼 표시하지 않습니다.

비상 시작/해제는 Pi가 검증한 P4 이벤트를 별도 emergency_state로 전송합니다.
비상 알림 수신으로 일반 상태의 seen_at을 갱신하지 않습니다.
일반 상태 갱신도 마지막 비상 이벤트를 지우지 않습니다.
비상 이벤트는 `--music-journal` SQLite의 alarm_outbox에 먼저 저장합니다.
서버가 DB 반영을 마친 뒤 version 2 emergency_ack(event_id, railing_id)를 반환해야 삭제합니다.
연결 단절/5초 대기열 만료/프로세스 재시작에도 미확인 이벤트는 남습니다.
난간별 한 이벤트씩 1초 간격으로 재전송하고 START 확인 후 END를 전송합니다.
발생 시각은 다시 쓰지 않으며 서버는 중복/이전 이벤트로 최신 상태나 통계를 덮어쓰지 않습니다.
웹은 기록된 비상 상태를 해제 이벤트까지 유지합니다. 오래된 START도 수신되면 표시할 수 있습니다.
Pi가 이벤트를 받기 전 또는 SQLite 저장 전에 전원이 끊기는 경우까지 보장하는 것은 아닙니다.
Pi/서버를 함께 업데이트하고 저널 파일을 삭제하지 마세요. DB 초기화는 필요 없습니다.
이번 보완만 적용할 때는 P4/WROOM/S3 펌웨어 변경이 필요 없습니다.

## 확인
1. 서버·Pi·P4 업데이트 후 웹에서 난간을 선택하고 마지막 수신 시간이 갱신되는지 확인.
2. 슬립/LED/감지 모드 변경 후 확인 상태에 반영되는지 확인.
3. P4 응답을 끊으면 새 수신 시각이 올라가지 않고 상태 지연이 나타나는지 확인.
4. 통화 중 일반 조회가 멈추고 종료 후 다시 수집되는지 확인.
5. 비상벨 이벤트가 일반 조회 없이 웹에 표시되고, 해제 후 비상 상태가 정리되는지 확인.

6. 선택하지 않은 난간/웹이 없는 상태에서 일반 SYSTEM 상태 요청이 없는지 확인.
7. 두 창에서 같은 난간을 열고 한 창을 닫아도 다른 창의 조회가 유지되는지 확인.

8. 서버 연결을 10초 이상 끊고 비상 시작/해제 후 재연결하여 순서대로 반영되고 재전송이 멈추는지 확인.
9. 서버 ACK 전에 Pi를 재시작하고 미확인 이벤트가 재전송되는지 확인.

## 선택/제어 후 최신성 표시
- 모니터링에서 난간을 선택하면 선택 당시 수신 시각보다 새로운 응답을 기다립니다.
  15초 동안 상태 확인 중, 그 이후에는 미수신/지연으로 표시합니다.
- Pi 연결 여부와 난간의 최신 상태 응답 여부를 별도로 표시합니다.
- 여러 난간 선택 시 일반 상세 상태를 첫 난간의 상태로 대체하지 않습니다.
- 제어 성공 후 Pi는 활성 조회 대상인 난간의 다음 조회를 앞당깁니다.
  통화/비상/제어 잠금 때문에 조회가 지연될 수 있으며 즉시 응답을 보장하지 않습니다.
- 이전 현장의 늦은 실패 응답으로 현재 현장의 표시를 덮어쓰지 않습니다.
- 편집 중인 옵션은 자동 덮어쓰지 않습니다. 이번 보완은 Pi/웹 업데이트가 필요하며 펌웨어 변경은 없습니다.
