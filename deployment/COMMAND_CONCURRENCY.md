# 여러 사용자·탭의 제어 요청

Spring Boot `/api/portal/commands`는 게이트웨이(Pi) 단위로 처리 중인 명령을 검사합니다. 같은 Pi 아래 난간들은 PLC 선로를 공유하기 때문입니다. 웹과 향후 앱은 같은 API를 사용해야 합니다.

- `QUEUED`, `SENT`, `RECEIVED` 요청이 있으면 새 요청은 HTTP 409로 거절합니다. 같은 사용자/다른 탭에도 적용합니다.
- 거절된 요청은 저장하거나 나중에 자동 실행하지 않습니다. 현재 결과를 확인한 뒤 필요하면 다시 누르세요.
- 통화 시작/수락도 검사 후 예약합니다. 일반 명령 뒤에 통화 예약만 먼저 생성하지 않습니다.
- PTT/종료 요청 처리 중에는 추가 요청도 기다립니다. 실패하여 UNKNOWN으로 확정되면 기존 종료 재시도를 사용할 수 있습니다.
- 다른 게이트웨이는 독립적으로 요청을 처리합니다. 현장 권한과 통화 소유권 검사도 유지합니다.

## 일괄 제어와 중복 요청

한 번에 여러 난간을 선택한 요청은 지원합니다. 대상 게이트웨이를 모두 검사하고 하나라도 처리 중이면 전체 요청을 거절합니다. 승인된 일괄 요청은 게이트웨이당 한 명령씩 결과를 기다리며 전송합니다. 모든 항목이 완료/실패/만료될 때까지 다른 요청은 받지 않습니다.

같은 사용자와 같은 request_id로 동일한 요청을 재전송하면 기존 결과를 반환합니다. 같은 ID에 다른 내용을 넣으면 거절합니다. HTTP 응답이 끊겼다고 새 ID로 무조건 다시 실행하지 마세요.

UNKNOWN은 장치 미적용을 뜻하지 않습니다. 시간 초과된 일반 제어는 실제 상태를 조회한 뒤 다음 조작을 결정해야 합니다. 통화는 기존 미확정 통화 보호를 유지하며 확인 없이 예약을 삭제하지 않습니다.

## 적용 및 범위

Spring Boot만 업데이트하고 재시작합니다. DB 초기화나 Pi·P4·WROOM·S3 업데이트는 필요 없습니다.

현재 단일 Spring Boot 프로세스의 동기화된 명령 서비스와 기존 DB 큐를 사용합니다. 여러 서버 인스턴스용 분산 락이나 장기 제어권 인수 기능은 아닙니다. Pi의 비상 이벤트 수신·음성 관리·상태 수집 스케줄도 변경하지 않습니다.

자동 테스트: 두 사용자 동시 요청 200/409 분리, 요청 ID 중복 방지, 거절된 요청의 통화 예약 방지, 일괄 순차 처리, 다른 게이트웨이 독립 처리, 여러 게이트웨이 요청의 부분 접수 방지. 실제 PLC 장치의 부하 시험은 별도입니다.
