# CCTV 사람 박스와 추정 나이 표시

## 적용
1. 서버 PC에서 최신 코드를 받습니다.
2. 기존 토큰과 DB를 유지해 Spring Boot를 재시작합니다.
3. analytics-server의 기존 프로세스를 종료하고 기존 config.json으로 다시 실행합니다:
   `python main.py --config config.json`
4. 로그인 후 /cctv-test.html을 Ctrl+F5로 새로고침하고 카메라 ID를 선택해 영상 보기를 누릅니다.
5. 난간 감지 모드를 CCTV로 설정해야 분석이 실행됩니다.
   MiVOLO가 ready이면 사람별 추정 나이를 표시합니다. 연령 분석이 꺼져 있어도 사람 박스는 표시됩니다.

CCTV Pi·난간 Pi·P4·WROOM·S3·MediaMTX·Nginx 설정 변경은 필요하지 않습니다.
DB 초기화나 토큰 재발급도 필요하지 않습니다.

## 표시
- 초록 박스: 기존 분석 ROI 안의 추적 중인 사람 (최대 20명).
- #ID 추정 28세: 동일 추적 이벤트에 속한 유효 나이 표본 2개 이상의 중앙값. 실제 나이를 보증하지 않습니다.
- 나이 분석 중 / 미확정 / 연령 분석 꺼짐 / 분석 불가: 숫자를 임의로 채우지 않습니다.
- 체크박스로 표시만 끌 수 있습니다. 전체 화면 버튼은 영상과 박스를 함께 확대합니다.
- 빈 프레임, 영상 정지, 조회 실패, 1초 이상 지난 메타데이터는 박스를 지웁니다.
- ID는 카메라 내 임시 추적 ID이며 사람 신원이나 카메라 간 동일 인물을 뜻하지 않습니다.
- 화면 나이와 난간 제어용 연령대는 목적이 다릅니다. 늦은 추정값이 표시되어도 이미 keep으로 종료한 음악 선택 이벤트를 다시 보내지 않습니다.

## 데이터 경로와 한계
원본 영상은 기존 SRT → MediaMTX → WHEP/WebRTC 경로를 유지합니다.
분석 서버는 정규화 좌표·ID·나이를 별도 최신값 워커로 약 5Hz 이하 HTTP POST합니다.
Spring Boot는 카메라 분석 토큰을 검사하고, 크기 제한(4KB/20명)과 좌표/나이를 검증합니다.
웹은 로그인 사용자의 카메라 권한 검사 후 약 5Hz 이하로 최신값을 읽습니다.
영상 재인코딩, DB에 프레임별 기록 저장, PLC 전송은 하지 않습니다.
재시도 적체 없이 새 프레임으로 덮어씁니다.

현재 OpenCV RTSP와 브라우저 WebRTC에 공통 프레임 PTS를 연결하지 않으므로
이 구현은 최신 프레임 기준 근사 오버레이이며 프레임 단위 동기화를 보장하지 않습니다.
프레임 수신 후 경과 시간과 HTTP 지연을 보수적으로 계산해 오래된 결과는 숨깁니다.
RTSP 내부 버퍼 지연 자체를 측정하지는 못합니다. 빠른 이동 또는 큰 영상 지연에서는 박스가 어긋날 수 있습니다.
분석이 800ms 이상 걸리면 박스가 표시되지 않을 수 있으므로 GPU/영상 해상도/분석 지연을 확인하세요.
정확한 녹화용 박스나 프레임 단위 정렬이 필요하면 공통 RTP/PTS 연계 또는 서버 합성 경로가 별도 필요합니다.

## 검증
- `python -m unittest discover -s analytics-server -p 'test_overlay.py'`
- monitoring-server에서 `node --test tools/cctv-overlay.test.cjs tools/cctv-age.test.cjs`
- monitoring-server에서 `mvn test -Dtest=CctvOverlayTest,CctvTest`
- 실제 카메라: 2명이 서로 다른 방향으로 움직일 때 박스/태그 추적, 전체 화면 비율, 분석 중지 후 박스 제거,
  다른 카메라/권한 없는 계정에서 결과 접근 차단, 기존 CCTV 난간 제어가 유지되는지 확인합니다.
