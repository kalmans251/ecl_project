# 웹 비상 통화 수락

## 적용
1. 서버와 난간 Pi를 같은 버전으로 업데이트합니다. DB 삭제/토큰 재발급은 필요 없습니다.
2. Spring Boot를 재시작하고 Pi는 기존 `--web-voice` 및 모니터링 연결 설정으로 재시작합니다.
3. 브라우저에서 Ctrl+F5로 새 JavaScript를 받습니다.
4. 현장 버튼 재누름 종료/슬립 복원에는 PR #93의 P4·S3 펌웨어도 필요합니다.

## 처리 순서
비상 수락 버튼은 `call.accept` 하나만 전송합니다. 서버가 사용자/현장 권한과
게이트웨이 통화 소유권을 확인하고 통화 ID를 예약합니다. Pi는 현재 활성 비상 이벤트를
확인하고 PLC 세션을 예약·저장한 뒤 비상 ACK(이벤트 번호 + 세션 번호)를 보냅니다.
P4 CALL START 확인 후에만 APPLIED/FIELD_TX를 반환하고 웹 음성을 연결합니다.
일반 `call.start`는 비상 ACK로 자동 전환되지 않습니다.

`emergency.ack` 단독 웹 명령은 더 이상 지원하지 않습니다. Pi 로컬 `ack 1`은 유지합니다.
비상이 이미 취소됐거나 핸들러가 없으면 NOT_STARTED로 서버 예약을 해제합니다.
PLC 송신 이후 결과가 불확실하면 UNKNOWN을 유지하며 통화 종료로 복구해야 합니다.
중복 요청 ID는 저장된 결과를 반환하며 같은 통화를 다시 시작하지 않습니다.

Pi가 동일 PLC 세션의 실제 END를 확인하면 `call_ended`를 서버에 전송합니다.
서버는 게이트웨이·난간·웹 통화 ID·PLC 세션 모두가 일치할 때만 통화 점유를 해제합니다.
Pi의 미확정/오프라인 상태를 END로 간주하지 않습니다. 종료 알림은 1초 간격으로
최대 30초 재전송합니다. 장시간 연결 단절이나 Pi 재부팅 뒤에는 수동 종료 복구가 필요할 수 있습니다.
웹 화면의 종료 반영은 기존 상태 갱신 주기의 영향을 받습니다.

## 실기 확인
- 비상벨 3초 → 웹 비상 수락 → 난간 음성 듣기 → 말하기/듣기 전환 → 웹 종료.
- 수락 전 현장 취소 후 웹 수락: 통화를 만들지 않고 예약이 해제되는지 확인.
- 비상 통화 중 현장 버튼 다시 3초: P4 END, Pi CALL ENDED, 웹 점유 해제 확인.
- 다른 사용자가 같은 게이트웨이에 통화를 중복 예약하지 못하는지 확인.
- 일반 통화 시작/종료도 기존처럼 동작하는지 확인.

호스트 Python/JavaScript/서버 통합 테스트와 실제 장비 음성 검증은 별개입니다.
