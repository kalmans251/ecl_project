# 웹 비상 통화 수락

## 적용
1. 서버와 난간 Pi를 같은 버전으로 업데이트합니다. DB 삭제/토큰 재발급은 필요 없습니다.
2. Spring Boot를 재시작하고 Pi는 기존 `--web-voice` 및 모니터링 연결 설정으로 재시작합니다.
3. 브라우저에서 Ctrl+F5로 새 JavaScript를 받습니다.
4. 현장 버튼 재누름 종료/슬립 복원에는 PR #93의 P4·S3 펌웨어도 필요합니다.

## 처리 순서
비상 수락 버튼은 `call.accept` 하나만 전송합니다. 서버가 사용자/현장 권한과
게이트웨이 통화 소유권을 확인하고 통화 ID를 예약합니다. Pi는 현재 활성 비상 이벤트를
확인하고 PLC 세션을 예약·저장한 뒤 비상 ACK(이벤트 번호 + 세션 번호)를 보냅니다.
P4 CALL START 확인 후에만 APPLIED/FIELD_TX를 반환하고 웹 음성을 연결합니다.
일반 `call.start`는 비상 ACK로 자동 전환되지 않습니다.

`emergency.ack` 단독 웹 명령은 더 이상 지원하지 않습니다. Pi 로컬 `ack 1`은 유지합니다.
비상이 이미 취소됐거나 핸들러가 없으면 NOT_STARTED로 서버 예약을 해제합니다.
PLC 송신 이후 결과가 불확실하면 UNKNOWN을 유지하며 통화 종료로 복구해야 합니다.
중복 요청 ID는 저장된 결과를 반환하며 같은 통화를 다시 시작하지 않습니다.

Pi가 동일 PLC 세션의 실제 END를 확인하면 `call_ended`를 서버에 전송합니다.
서버는 게이트웨이·난간·웹 통화 ID·PLC 세션 모두가 일치할 때만 통화 점유를 해제합니다.
Pi의 미확정/오프라인 상태를 END로 간주하지 않습니다. Pi는 기존 통화 소유 기록과
동일 세션의 확인된 END를 대조하고 `web_call_ends`에 저장합니다. 이 기록은 서버의
`call_end_ack`가 올 때까지 유지하며 재연결/재시작 후에도 재전송합니다.
서버 ACK의 통화 ID·난간·세션이 모두 일치해야 기록을 삭제합니다.
1초마다 최대 4개씩 순환 전송하므로 오래된 기록 하나가 새 종료 알림을 막지 않습니다.
테이블은 기존 Pi 웹 통화 저널에 자동 생성되며 DB를 지우면 안 됩니다.

PLC END 자체를 받지 못했거나, 기록을 저장하기 전에 Pi 전원이 끊겼다면 종료를
추정하지 않습니다. 이런 경우는 기존의 수동 종료 복구가 필요합니다.
서버가 아직 PLC 세션 번호를 확정하지 못한 UNKNOWN 통화는 이 알림만으로
해제하지 않습니다. 기존 통화 종료 버튼으로 세션을 확인하며 복구합니다.
구버전 서버는 새 수신 확인을 보내지 않으므로 서버와 Pi를 함께 업데이트하세요.
웹 화면의 종료 반영은 기존 상태 갱신 주기의 영향을 받습니다.

## 실기 확인
- 비상벨 3초 → 웹 비상 수락 → 난간 음성 듣기 → 말하기/듣기 전환 → 웹 종료.
- 수락 전 현장 취소 후 웹 수락: 통화를 만들지 않고 예약이 해제되는지 확인.
- 비상 통화 중 현장 버튼 다시 3초: P4 END, Pi CALL ENDED, 웹 점유 해제 확인.
- 다른 사용자가 같은 게이트웨이에 통화를 중복 예약하지 못하는지 확인.
- 일반 통화 시작/종료도 기존처럼 동작하는지 확인.

호스트 Python/JavaScript/서버 통합 테스트와 실제 장비 음성 검증은 별개입니다.

## 수락 시 난간 선택
비상 알림만으로 현재 선택을 바꾸지 않습니다. 수락 버튼을 누르면 호출 대상을 고정하고,
오디오 준비 후 호출이 여전히 유효한지 확인한 뒤 해당 난간 하나를 선택합니다.
기존 미적용 제어 설정은 비우며 다른 난간에 전달하지 않습니다.
수락 처리 중에는 중복 수락/일반 명령/선택 변경을 막습니다. 내 통화가 이미 있으면 먼저 종료해야 합니다.
여러 호출은 현재 팝업을 덮어쓰지 않고 닫은 뒤 다음 웹 갱신에서 순차 표시합니다.
오디오 준비 실패/호출 해제는 기존 선택을 유지합니다. 실제 수락 전송 이후 실패하면
해당 난간을 선택한 채 오류를 표시하므로 처리 내역/통화 종료 복구를 확인할 수 있습니다.
서버의 권한 및 통화 점유 검사는 계속 최종 기준입니다.

## 관제 PC 비상 알림음
모니터링 상단의 `비상 알림음 활성화`를 사용자 클릭으로 한 번 눌러 브라우저 재생을 허용합니다.
페이지 새로고침/재접속 후 다시 활성화해야 할 수 있으며 상태 문구로 확인합니다.
현재 현장의 수신된 비상 상태를 기준으로 WROOM과 동일한 880/660Hz 사각파를 350ms 간격으로 반복합니다.
실제 소리 크기/음색은 PC 스피커와 볼륨 설정에 따라 다릅니다. 현장 오디오를 스트리밍하는 방식은 아닙니다.
팝업 닫기는 소리를 끄지 않습니다. `현재 호출 알림음 끄기`는 현재 비상들만 음소거하며 새 호출은 다시 울립니다.
내 통화가 진행 중이면 알림음을 일시정지합니다. 통화 종료 후 미처리 호출이 남으면 다시 울립니다.
비상 해제나 현장 변경 시 해당 알림은 멈춥니다. 서버 조회 실패만으로 비상 해제를 추정하지 않습니다.
여러 호출의 소리는 한 개로 합칩니다. 여러 브라우저 탭은 각각 재생하므로 관제 탭 한 개에서만 활성화하세요.
브라우저/OS의 절전, 음소거, 탭 종료 상태까지 소리 전달을 보장하지 않습니다.
