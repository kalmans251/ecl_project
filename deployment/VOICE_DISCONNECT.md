# 웹 통화 연결 종료와 복구

브라우저의 현재 음성 WebSocket이 닫히면 서버는 그 시점부터 약 15초의 재연결 유예를 계산합니다.
이전에는 통화 시작/PTT 작업 시각을 사용하여 오래 통화한 뒤 연결이 끊기면 유예 없이 UNKNOWN으로 바뀔 수 있었습니다.
교체된 이전 소켓의 종료는 현재 연결에 영향을 주지 않습니다. 전송 오류는 소켓을 닫고 같은 정리 절차로 처리합니다.

유예 중 새 음성 연결이 정상 바인딩되면 통화를 유지합니다. 유예가 지나면 서버는 UNKNOWN으로 표시하고 Pi에 voice.pause를 보냅니다.
Pi는 웹 통화의 유지 갱신을 멈추며 P4는 마지막 유지 신호로부터 10초 후 종료 절차를 시작합니다.
따라서 브라우저 종료 순간에 즉시 종료되는 방식이 아니며, 서버 스케줄/통신 지연도 더해집니다.
게이트웨이 자체 연결 단절은 별도의 기존 처리로 즉시 UNKNOWN이 될 수 있습니다.

실제 P4 END를 Pi가 확인하고 서버에 전달해야 통화 점유가 해제됩니다. 시간만 지났다고 성공으로 표시하지 않습니다.
END가 없으면 수동 종료 복구가 필요합니다. 서버가 TCP 연결 종료/오류를 아직 감지하지 못한 무응답 연결의 감지 시간까지 이 변경이 보장하지는 않습니다.

이번 변경은 Spring Boot 업데이트/재시작만 필요합니다. DB·토큰·펌웨어 변경 불필요.

실기 확인:
1. 30초 이상 통화 후 탭 종료: 서버 유예 로그와 뒤이은 P4 END 확인.
2. 연결을 끊었다가 15초 안에 다시 바인딩: 통화 유지 확인.
3. 새 소켓 연결 뒤 이전 소켓 종료: 현재 통화가 끊기지 않는지 확인.
4. PLC 응답을 끊은 상태: END 확인 없이 서버 점유를 임의 해제하지 않는지 확인.
