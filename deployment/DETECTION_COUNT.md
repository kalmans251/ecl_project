# 난간 누적 감지 카운트 조회·초기화

## 적용 순서
1. PR 병합 후 최신 코드를 받습니다.
2. **P4 펌웨어를 빌드·업로드**합니다.
3. **난간 Pi 프로그램과 Spring Boot를 업데이트·재시작**합니다.
4. 웹에서 Ctrl+F5를 누릅니다. WROOM/S3/CCTV Pi/분석 서버 변경은 필요 없습니다.

기존 모니터링의 레이더/CCTV 카드와 기능 테스트 화면에 카운트 조회·초기화 버튼이 있습니다.
실제 P4에 조회한 마지막 값과 요청 시각을 표시하며, 웹 자동 갱신은 PLC 카운트를 자동으로 읽지 않습니다.
현재 시점의 값을 확인하려면 카운트 조회를 누릅니다. 미조회는 0으로 표시하지 않습니다.

## 의미
- `total_detected_count`는 선택된 감지 모드에서 인정한 신규 감지 이벤트의 누적 횟수입니다.
- 현재 화면에 남은 사람 수, 고유 방문객 수, YOLO 추적 ID와 다릅니다.
- 레이더/CCTV 모드를 바꿔도 같은 누적값을 유지합니다. P4 재부팅 시에는 0으로 초기화됩니다.
- 초기화는 누적 횟수만 0으로 만듭니다. 연령대 통계·음악 선택·감지 모드·슬립 활동 시각·중복 이벤트 기록은 유지합니다.
- 초기화 직후 새 감지가 들어오면 바로 1 이상으로 증가할 수 있습니다.

## 확인 응답
웹에서 대상 난간을 선택하고 초기화를 확인하면 기존 명령 권한·게이트웨이·난간 식별 경로로 전송됩니다.
P4가 해당 요청 ID에 대해 0으로 초기화한 응답을 보내야 APPLIED입니다.
실패/타임아웃에서는 화면 값을 임의로 0으로 바꾸지 않으며 자동 재전송하지 않습니다.
통화·비상 중에는 기존 일반 제어 제한이 적용됩니다.

Pi 콘솔/수동 하드웨어 테스트:
```
detection 1 count
detection 1 reset
detection 1 count
```
사람을 새로 감지시킨 후 다시 조회해 증가를 확인하세요. 기존에 계속 추적 중인 사람은 새 이벤트가 아닐 수 있습니다.

## 프로토콜
- Service DETECTION=0x09, 기존 APPLY=0x28 래퍼와 APPLY_RESULT=0x29 사용.
- 조회 원 명령: STATUS_REQUEST=0x10, payload 없음.
- 초기화 원 명령: DETECTION_RESET=0x36, payload 없음.
- 성공 결과: request_id[4] + original_command[1] + status=0[1] + schema=1[1] + source[1] + total_count[4, big-endian].
- source: 0=레이더, 1=CCTV. 초기화 확인은 count=0이어야 합니다.
- 웹 operation: detection.count(COMPLETED), detection.reset(APPLIED), value 없음.
- Pi의 영속 요청 저널은 같은 웹 요청 재전송을 실행하지 않습니다. P4는 최근 초기화 요청 ID/난간의 중복 프레임을 재실행하지 않고 기존 확인을 반환합니다.

## 검증
호스트에서 P4 실제 detection_manager와 APPLY 분기, Pi 응답 검사/중복 방지, 서버 결과 검증, 웹 카운트 표시를 테스트합니다.
실제 장비에서는 증가 → 초기화 확인 → 다음 신규 감지 증가를 확인해야 합니다.
