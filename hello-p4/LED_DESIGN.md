# LED 디자인 재현

참조: `kalmans251/ECO_LUMINOUS_PROJECT-ESP32_P4`의
`3e93790dffeb21041f6dd66a74e90ac1e30ae612` / `main/main.c`.
기존 코드를 통째로 가져오지 않고, 표시 규칙을 독립적인 `led_design.c`로 재구현했습니다.
현행 명령 큐, 시스템 상태, 음악 EQ 입력, 절전 및 통화 정책을 사용합니다.

## 배치와 선택

좌우 각각 4행 × 31열(124개), 총 248개입니다. 행마다 배선 방향이 반대인
serpentine 인덱스를 유지합니다. GPIO와 GRB 드라이버 설정은 그대로입니다.
Pi CLI 패턴 번호는 1부터, PLC와 서버 API의 패턴 번호는 0부터 시작합니다.

| 선택 | 모습 | 프레임 간격 |
|---|---|---|
| `led 1 basic 1` | 가로 한 줄이 4층을 위아래 왕복, 층마다 2프레임 유지 | 80ms |
| `led 1 basic 2` | 행·열 위상이 다른 밝기 파동, 좌우 색 배합 차이 | 20ms |
| `led 1 basic 3` | 실제 배선 경로를 따라 이동하는 20픽셀 꼬리 | 10ms |
| `led 1 basic 4` | 중앙 15열에서 양끝으로 갈라지는 세로선 | 30ms |
| `led 1 basic 5` | 4열 간격의 빗줄기와 70% 잔상 | 60ms |
| `led 1 basic 6` | 층별 색 블록 교대 | 250ms |
| `led 1 weather clear` | 기본 6개 패턴을 10초마다 순환 | 패턴별 |
| `led 1 weather cloudy` / `rain` | 홀수 열 15개의 색 빗방울, 4층 낙하 후 잔상 | 200ms |
| `led 1 weather snow` | 최대 18개 반짝임, 서로 붙지 않는 위치와 점진적 밝기 변화 | 25ms |
| `led 1 music 1` | 중앙이 높은 무지개 언덕형 막대 | 15ms |
| `led 1 music 2` | 저음에 반응하여 한쪽부터 뻗는 파동 | 12ms |
| `led 1 music 3` | 저음에 반응하여 중앙에서 좌우로 퍼지는 파동 | 12ms |

프레임 간격은 목표값이며 FreeRTOS tick과 RMT 출력 시간에 영향을 받습니다.
`led 1 basic` / `led 1 music`은 마지막에 선택한 해당 모드의 패턴을 유지합니다.
기본값은 각 모드의 첫 패턴입니다. 전원 재시작 뒤에는 기본값으로 돌아옵니다.

참조 코드의 색 함수는 매개변수를 B/G/R이라고 부르지만 최종적으로 RGB API에
그 순서 그대로 전달합니다. 주석에 적힌 색 이름 대신 **실제 RGB 드라이버 인수**를
재현했습니다. 예를 들어 통화/비상 점멸의 드라이버 RGB 값은 `(0,0,255)`입니다.
실물 LED 모델과 배선에 따른 최종 색은 현장에서 확인해야 합니다.
눈 효과는 개수·간격·확률·수명·팔레트 규칙을 재현하며, 난수 발생기가 달라
매 실행마다 참조와 동일한 픽셀 순서가 되지는 않습니다.

## 기존 보호 동작

- LED OFF 또는 실제 절전 상태이면 LED 출력을 끕니다.
- 모드·패턴 변경과 절전 복귀 시 이전 프레임/잔상을 초기화합니다.
- 맑음 순환은 모드 진입부터 시간을 계산합니다.
- 음악 정지, 통화 중 또는 EQ 수신이 500ms 이상 끊기면 음악 효과를 비웁니다.
  유효한 EQ의 값이 0인 경우에만 참조의 낮은 진폭 움직임을 재현합니다.
- 통화/비상 점멸은 기존 우선순위를 유지하며 300ms 주기입니다.
- 음악 PCM 출력이나 SD 읽기, WROOM/S3 태스크는 수정하지 않습니다.

## 프로토콜

LED SET의 기존 1바이트 모드 명령은 그대로 지원합니다.
기본/음악 모드에서 선택적 두 번째 바이트가 패턴 번호입니다.
`01 00..05`는 기본, `03 00..02`는 음악입니다.
날씨의 기존 `02 <weather>` 형식은 그대로입니다.
잘못된 길이/번호 또는 명령 큐 포화 시 상태를 바꾸지 않습니다.
현재 SYSTEM 상태 응답에는 세부 패턴 번호가 없으므로 서버는 이 명령을
장치 적용 확인(APPLIED)으로 표시하지 않습니다.

## 검증 및 실물 테스트

호스트 검사: `python -m unittest discover -s hello-p4/tests -v`.
네이티브 C 렌더러를 컴파일하여 타이밍, 매핑, 색, 잔상, 눈 간격,
음악 입력 만료, 통화 우선순위와 시계 wraparound를 검사합니다.
개발 중 참조와 기본 6개·비/흐림·음악 3개를 각 120프레임 비교했으며
좌우 248픽셀의 채널 차이는 최대 1 이내였습니다.
전체 펌웨어 빌드는 GitHub Actions의 ESP-IDF v6.0.2 작업으로 확인합니다.

새 P4 펌웨어와 Pi 코드를 적용한 후 위 명령으로 패턴을 하나씩 확인하세요.
음악 패턴은 음악을 재생한 상태에서 검사합니다. 이어서 LED OFF/ON,
절전 진입/복귀, 통화 시작/종료 때 잔상이나 음악 정지 후 움직임이 없는지 확인합니다.
서버 화면의 패턴 선택도 활성화했지만, 실물 연결은 별도 Pi WebSocket 어댑터가 필요합니다.
