# 누적 감지 카운트 변경을 웹에 바로 전달

기존 5초 P4 상태 조회와 2초 웹 조회의 중첩 대기를 줄입니다.
카메라/레이더의 감지 확정 및 누적 집계 기준은 변경하지 않습니다.
웹에서 현재 사람 수나 분석 추적 ID로 누적값을 추정하지 않습니다.

## 경로

1. 난간 Pi의 기존 EVENT_POLL 요청에 기능 식별 바이트 `01`을 붙입니다.
2. P4는 비상·통화 종료/오류 보고가 없을 때, 기존 응답에 선택 감지원과 최신 누적값을 함께 보냅니다.
3. Pi는 확인된 카운트가 바뀌면 WSS로 서버에 전달합니다. 변경이 없으면 최대 5초마다 연결 복구용 최신값을 재전달합니다.
4. 서버는 현장 권한과 게이트웨이 매핑을 검증한 후 해당 난간을 보는 웹에 WebSocket으로 전달합니다.
5. 웹은 카운트만 갱신하며 일반 상태 수신 시각, 슬립 상태, 장치 온라인 상태는 갱신하지 않습니다.

PLC 요청 횟수와 이벤트 확인 주기는 유지합니다. P4는 Pi 요청 없이 임의 송신하지 않습니다.
카운트는 최신값으로 합쳐 전달하므로 여러 명이 연달아 포착되면 한 번에 여러 명 증가할 수 있습니다.
초기화/재부팅으로 0 또는 작은 값이 오는 경우도 실제 P4 확인값으로 반영합니다.
기존 수동 카운트 조회·초기화와 일반 상태 조회는 유지합니다.

한 난간 환경에서는 다음 이벤트 확인 기회까지의 대기와 통신 시간이 주된 지연입니다.
Pi의 이벤트 확인 루프는 250ms 대기 뒤 한 난간씩 순환하며, 실제 응답·버스 점유·실패 시간도 추가됩니다.
서버는 최대 약 100ms 주기로 최신값을 브라우저에 전달합니다.
여러 난간, 통화/비상, PLC 재시도, 인식 필터·영상 분석 지연에서는 더 늦을 수 있으며
고정 지연시간을 보장하지 않습니다. 특히 전체 난간 수에 따른 순환 지연은 남습니다.

## 적용 순서

1. 관제 서버를 먼저 업데이트·재시작합니다. 구형 서버는 새 메시지를 지원하지 않습니다.
2. 난간 Pi 코드를 업데이트합니다. **CCTV 전용 Pi가 아니라 PLC에 연결된 Pi**입니다.
3. P4를 빌드·업로드합니다.
4. 난간 Pi의 `main.py`를 기존 토큰/인자 그대로 재시작합니다.
5. 웹에서 Ctrl+F5를 누르고 난간 하나를 선택합니다. CCTV/레이더 어느 화면이든 구독합니다.

WROOM·S3·CCTV 전용 Pi·분석 서버는 이번 변경으로 업데이트할 필요가 없습니다.
P4 재부팅은 기존 정책대로 누적값을 초기화하므로 현장 검증 시 참고합니다.

신규 Pi는 확장 요청에 응답하지 않는 구형 P4를 처음 한 번 확인한 후 기존 요청으로 돌아갑니다.
구형 P4 감지 결과는 Pi를 재시작할 때까지 유지하므로 P4 업로드 후 반드시 Pi를 재시작합니다.
신규 P4는 기존 Pi의 8바이트 요청에는 기존 16바이트 응답을 유지합니다.
따라서 Pi/P4 순차 업데이트 중 기존 비상 이벤트 경로가 유지됩니다.

## 프로토콜 및 우선순위

- EVENT_POLL payload: token[4] + ack[4] + capability=1[1]. 기존 8바이트도 허용.
- 확장 유휴 EVENT_REPLY payload(21): token[4] + event_id=0[4] + dropped[4] + service=0[1] + command=0[1] + sleep_active[1] + projector[1] + source[1] + total_count[4, big-endian].
- source: 0=레이더, 1=CCTV. 일반 상태와 같이 P4 detection_manager의 값을 사용.
- 기존 비상·통화 이벤트의 형식과 ACK 처리는 유지하고 카운트보다 우선합니다.
- 21바이트 payload는 최대 비상 응답(24바이트)보다 작아 기존 PLC 응답 시간 예산 안에 들어갑니다.
- Pi 메시지: `version=1,type=detection_state,railing_id,observed_at,source,count`.
- 웹 경로: `/ws/operator/detection/{rail_id}`. 같은 Origin의 로그인 세션 및 현장 조회 권한 필요.
- 계수는 uint32 범위로 검증합니다. 지연·잘못된 토큰·다른 난간 응답은 반영하지 않습니다.
- 서버는 최신값만 메모리에 보관하고 느린 브라우저 처리를 게이트웨이 수신 스레드와 분리합니다.

## 현장 확인

일반 모드와 슬립 기능 ON 상태 각각에서 사람을 새로 진입시켜 P4 집계와 웹 표시 시점을 비교합니다.
CCTV/레이더 전환, 0 초기화, Pi/서버 재연결, 난간 전환 후 값 격리도 확인합니다.
통화 종료 및 비상 이벤트 처리가 유지되는지 확인합니다.
웹 탭을 숨기면 카운트 구독을 끊고 복귀하면 최신값을 재구독합니다.
