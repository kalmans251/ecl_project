# 배터리 전압·태양광 입력 측정

12.8V(4S) LiFePO4 배터리 단자 전압으로 **추정 잔량**을 표시한다.
태양광 충전선의 전류는 부하 소비 전류나 배터리 순충전 전류가 아니다.
현재 구현은 V/A/W와 추정 %이며 누적 Wh, 정밀 SOC, 충전 제어, 저전압 차단을 하지 않는다.

## 현재 장비 기본 설정

| 센서 | 용도 | 션트 |
|---|---|---|
| 1번 / 0x40 | 좌측 태양광 입력 전류·전력 | R100 = 0.1Ω = 100mΩ |
| 2번 / 0x41 | 우측 태양광 입력 전류·전력 | R100 = 0.1Ω = 100mΩ |

배터리 단자 전압을 측정한다는 현장 설명에 따라 **1번 전압을 잔량 추정에 사용**하도록
기본 설정한다. 별도 배터리 전류 센서로 취급하지 않는다. 두 전압을 더하거나 평균내지 않는다.
좌/우 전류 역시 태양광 입력 전류이며 부하 전류나 배터리 순충전 전류가 아니다.
측정 위치가 패널 측으로 바뀌면 배터리 채널을 0으로 해제해야 한다.

## 배포와 실제 배선 설정

1. 서버와 Pi를 업데이트하고 재시작한다. DB 초기화는 필요 없다.
2. `hello-p4`에서 `idf.py menuconfig` → `Railing energy measurements`를 연다.
3. Battery terminal voltage channel: `1`은 0x40(좌측), `2`는 0x41(우측).
   **VIN-와 GND 사이가 실제 배터리 단자 전압인 채널만** 선택한다.
   기본값은 `1`이다. `0`으로 설정하면 잔량을 만들지 않는다. 다른 채널로 자동 대체하지 않는다.
4. 두 센서 각각의 **실제 션트 저항**을 mΩ으로 입력한다.
   예: 부품/회로도로 0.1Ω임을 확인했다면 100mΩ. 센서 칩 이름만으로 저항값을 추정하지 않는다.
   두 채널의 기본값은 `100`이다. `0`으로 설정하면 전압만 표시하고 해당 전류·전력은 미확인으로 둔다.
   입력 전류의 양(+) 방향은 VIN+ → VIN-. 음수도 보존하므로 반대 배선/역류를 숨기지 않는다.
   이전 PR 버전에서 이미 sdkconfig에 0을 저장했다면 기본값 변경만으로 덮어쓰지 않는다.
   menuconfig에서 배터리 채널 `1`, 좌/우 션트 `100`으로 변경하고 저장한다.
5. `idf.py build flash monitor`로 **P4**를 빌드·업로드한다. WROOM/S3 변경은 없다.
6. 웹에서 난간 하나를 선택한다. P4 로그 `ENERGY`에서 채널 ready 여부를 확인한다.
   멀티미터와 전압을 비교하고, 기준 전류로 션트 설정을 검증한다.
   센서를 분리하면 다음 상태 수집에서 값이 미확인으로 바뀌어야 한다.

기존 SDA GPIO8 / SCL GPIO9, 0x40 / 0x41 사용. I2C 100kHz, 낮은 우선순위에서
1초마다 두 채널을 읽는다. 각 I2C 작업은 최대 30ms, PLC 처리에서는 캐시만 복사한다.
배터리와 입력 전압은 1/8 지수 평균(약 수 초), 전류는 최신 샘플이다.
실패 시 즉시 무효화하고, 3초 넘은 캐시는 전송하지 않는다. 재연결 시 평균을 새로 시작한다.
INA219의 측정 가능 전압은 26V 이내다. 연결된 회로와 풀업 전압을 확인한다.

## 전송 호환성

SYSTEM/APPLY STATUS payload `[1]`: 기존 16바이트 그대로.
새 Pi는 `[2]`를 요청한다. 명시적으로 거절하는 이전 P4에는 `[1]`로 돌아가
일반 제어 상태는 유지한다(해당 연결 동안). 시간 초과/버스 점유는 재전송하지 않는다.
업데이트 후에는 Pi를 재시작하여 v2를 다시 탐색한다.
상태 수집 주기 5초, 웹 선택 난간 demand, 통화 우선 정책은 유지한다.

v2 응답은 31바이트: 기존 상태 16바이트(첫 바이트=2) + 아래 15바이트.
모든 정수는 big-endian. PLC 전체 프레임 47바이트(결과 헤더6 + 상태31 + 프레임10).

| 확장 오프셋 | 내용 |
|---|---|
| 0 | 유효 비트: 0 좌전압, 1 우전압, 2 좌전류, 3 우전류, 4 배터리전압 |
| 1–2 | 배터리 mV u16 |
| 3–4 / 5–6 | 좌/우 mV u16 |
| 7–10 / 11–14 | 좌/우 mA i32 (부호 유지) |

미확인 값은 JSON에서 생략한다. 서버가 새 snapshot으로 대체하므로 오래된 측정값이
남지 않는다. 웹도 일반 상태 신선도 조건을 적용해 연결 단절/다중 선택 때 숫자를 지운다.

## 추정 잔량의 한계

Pi `status_sync.py`의 `SOC_CURVE`는 Renogy의 공개 4S LiFePO4 참고 표를 사용한다:
https://www.renogy.com/blogs/general-solar/lifepo4-voltage-chart
13.0V의 중복 40/50%는 중간 45%로 통합하고 구간 보간 후 5% 단위로 반올림한다.
**사용자의 배터리 제조사에 맞춰 보정된 표가 아니다.** 실제 제품 자료가 생기면 교체한다.
충전·부하·온도를 알 수 없으므로 약 100%도 완충 확인을 의미하지 않는다.
표의 저전압 지점은 방전 허용 기준이 아니며 보호/충전 제어에 사용하면 안 된다.
웹에 `약 N%`, `전압 기준 추정 · 충전/부하에 따라 오차 있음`을 표시한다.

INA219 변환 기준: bus register >>3 ×4mV, signed shunt ×10µV / 실제 션트 Ω.
https://www.ti.com/lit/ds/symlink/ina219.pdf
I2C 드라이버: ESP-IDF master driver (`esp_driver_i2c`).
https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32p4/api-reference/peripherals/i2c.html

## ENERGY 진단 로그 (측정값이 미확인일 때)

시작 시 실제 SDA/SCL, 속도, 채널/션트 설정을 출력한다. 설정 로그만으로 센서 응답을
확인한 것은 아니다. 첫 측정 실패도 경고하며 같은 실패 상태는 채널별 10초 간격으로
다시 출력한다. 정상↔실패 전환은 즉시 출력한다. 성공 시 bus_mV와 shunt_uV도 표시한다.

실패 로그의 `channel`, `addr`, `stage`, `error`, `read_mask`, `raw_bus`, `raw_shunt`를 확인한다.

| stage | 의미 |
|---|---|
| config_write | INA219 설정 쓰기 실패 |
| bus_read | 버스 전압 레지스터(0x02) 읽기 실패 |
| shunt_read | 션트 전압 레지스터(0x01) 읽기 실패 |
| conversion_not_ready | 읽기는 성공했지만 CNVR=0 |
| overflow | OVF=1로 유효성 검사 탈락 |
| bus_out_of_range | 버스 전압이 허용 측정 범위 초과 |
| shunt_saturated | 션트 전압이 설정된 ±320mV 범위 끝에 도달 |

`error=ESP_OK`여도 뒤의 값 검증에서 실패할 수 있다. `read_mask`의 bit0은 버스 전압,
bit1은 션트 전압을 실제로 읽었다는 뜻이다. 해당 bit가 0일 때 raw=0은 측정된 0V가 아니다.
I2C 초기화/장치 핸들 등록/태스크 생성 실패도 별도로 표시한다.
진단은 기존 유효성 검사나 전류·잔량 계산을 우회하지 않는다. 하드웨어 고장 여부는
이 로그만으로 단정하지 않고 배선·센서 전원·주소·읽은 값을 대조한다.


## 변환 대기와 재설정

P4의 CONFIG_FREERTOS_HZ=100에서는 5ms가 0틱으로 변환되어 기존 초기 대기가
실제로 수행되지 않았다. 초기 설정 또는 I2C 오류 복구 후에는
`pdMS_TO_TICKS(20)+1`틱 대기하여 변환 시간을 확보한다.
CNVR=0이면 해당 표본은 미확인으로 유지하고 다음 주기에 다시 읽는다.
변환 미완료나 범위 검사 실패만으로 설정을 다시 쓰지 않는다. I2C 통신 오류가
발생한 경우에만 다음 주기에 재설정한다.

적용 대상은 P4 펌웨어이다. 업데이트 후 ENERGY의 ready 로그와 실제 배터리 단자
전압을 대조한다. 호스트 회귀 테스트는 100Hz 틱과 반복 CNVR=0, 이후 정상 회복,
I2C 오류 후 재설정을 검사한다. 실제 센서와 ESP-IDF 빌드 검증은 별도로 필요하다.


## 웹 잔량 표시

선택 난간의 배터리는 잔량을 먼저 표시하고 전압을 함께 표시한다.
예: **약 70% · 13.18 V**. 아래에 잔량 막대와 ‘전압 기반 추정’ 설명을 둔다.
Pi의 기존 전압 기준표를 사용하며 브라우저에서 별도 환산하지 않는다.
미수신·유효하지 않은 값은 미확인으로 표시한다(측정된 0%와 구분).
이 화면 변경은 서버 업데이트·재시작 후 브라우저 강력 새로고침으로 적용한다.
이미 전압과 추정 잔량을 전송하는 Pi 및 P4 펌웨어의 변경은 필요 없다.
