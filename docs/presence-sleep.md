# 사람이 남아 있는 동안 슬립 방지

기존 NEW_PERSON 이벤트는 누적 인원수와 연령 분석 연결에 사용합니다.
슬립 판단은 신규 입장뿐 아니라 현재 존재 신호로도 마지막 감지 시각을 갱신합니다.

- CCTV: 기존 분석 observation의 available=true, people>0일 때 서버가 최대 2초에 한 번 관할 Pi에 짧은 존재 신호를 보냅니다. 관제 웹을 열어둘 필요는 없습니다.
- Pi: 난간별 최신 신호 하나만 보관하고 유효기간(최대 3초)을 확인합니다. 기존 PLC 잠금을 즉시 얻을 수 없거나 통화 중이면 건너뛰며 오래된 신호를 재전송하지 않습니다.
- 레이더: 앞뒤 두 레이더 중 하나라도 유효한 최근(1초 미만) 프레임에 안정화된 사람이 있으면 S3가 2초에 한 번 존재 신호를 보냅니다. 좌표를 한 센서에서만 수집하는 설정과 별개입니다.
- P4: 현재 선택된 감지원의 신호만 인정합니다. 센서 수신 OFF이면 무시합니다. 누적 인원수, 연령 통계, 새 트랙 번호는 추가하지 않습니다.
- 사람이 사라지거나 분석/통신이 끊기면 신호 갱신이 중단되고 마지막 유효 신호 이후 기존 10초 타이머가 적용됩니다. 음악 LED 모드에서는 기존 곡 종료 대기 정책이 유지됩니다.
- 이미 슬립 상태라면 존재 신호도 기존 wake 경로를 사용합니다. 진행 중인 연령 결과 대기는 변경하지 않습니다.

PLC 데이터: SERVICE_DETECTION/CMD_DATA [4]는 Pi의 CCTV 존재, [5]는 S3의 레이더 존재입니다.
CCTV는 기존 APPLY 요청·응답을 사용합니다. presence 메시지는 일반 명령 저널에 기록하지 않습니다.
연결이 끊기면 Pi 메모리의 대기 신호도 폐기됩니다.

적용: 서버/Pi/P4 업데이트. 레이더도 사용할 경우 S3 업데이트. WROOM 변경 없음.
CCTV 분석 프로그램은 기존 observation API를 그대로 사용하며 수정할 필요가 없습니다.
신호 지연·누락이 10초 이상 계속되면 안전한 무기한 켜짐 대신 기존 슬립이 적용될 수 있습니다.

검증: Pi 최신 신호 병합/만료/연결 해제/미등록 난간 및 P4 존재 지속 30초/카운트 불변/마지막 신호 후 10초 만료 테스트.
전체 Java·펌웨어 빌드와 현장 검증은 별도로 필요합니다.
